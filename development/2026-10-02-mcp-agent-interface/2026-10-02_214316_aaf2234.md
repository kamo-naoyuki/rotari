# Reorder the agent interface plan around trial findings

## Change
Rewrote `plan.md`. The purpose, principles, and decisions now treat the CLI (with `--json`) as the terminal agent interface and MCP as a thin adapter for clients without a shell. Added a "Gaps found by the trial" table mapping each gap to a shared capability. Updated the shared behavior map with the new capabilities and the milestone in which MCP exposes each. Replaced the milestones with M0 (retire `rotari-agent`, clean up the prototype) through M7, putting failure grouping (M1), excerpts and cause-aware comparison (M2), and discovery and progress (M3) before read-only MCP tools (M4).

## Reason
The [agent trial](agent-trial-2026-10-02.md) showed that agents lack compact, decision-ready information rather than entry points. The previous plan centred on a generic object query and a protocol-neutral layer shared by `rotari-mcp` and `rotari-agent`, which would have rebuilt CLI behavior without addressing that gap.

## Plan impact
Decisions made: no `rotari-agent` (it duplicates `rotari show --report`); task-shaped MCP tools instead of a generic query tool; no `available_operations` in results; read and changing operations are separate tools so MCP clients' per-tool approval can gate changes. Dropped open decisions about the generic query (object kinds, one query tool versus several). New open decisions: the owner package of failure grouping and error-line normalization, output limits, and the progress cursor format. Every milestone is now checked by repeating the trial.

## Validation
Documentation only; no tests apply. Checked that the packages, commands, and flags the plan names exist in the current tree.

## Remaining
M0 is next: remove `cmd/mcp/agent`, resolve MCP targets through the registry instead of a raw basedir, return structured fields, make `rotari-mcp` exit non-zero on failure, and update `docs/ARCHITECTURE.md`. Then M1, failure grouping.
