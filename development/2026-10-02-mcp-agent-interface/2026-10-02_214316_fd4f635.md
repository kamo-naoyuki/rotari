# Record an agent trial of triage with the existing CLI

## Change
Added `agent-trial-2026-10-02.md`, a step-by-step record of an agent (Claude Code, with a shell) triaging failed runs and running a fix-and-rerun loop using only the current `rotari` CLI, with each call's exit status and output size. Added `agent-trial-fixture.sh`, which builds the binary and recreates the trial's three basedirs: mixed failure causes (`labA`), a same-named healthy project (`labB`), and a 300-task array with 84 failures (`labC`).

## Reason
The plan's interaction model was designed from the human side. Before building agent interfaces, the trial measured what an agent actually needs and where the current CLI already suffices, so the plan could be driven by evidence rather than by mirroring CLI commands.

## Plan impact
Established that run-ID resolution, `show -r RUN_ID --json` per-job diagnoses, and `lineage RUN1 RUN2` already serve agents. The main gap is volume: triaging the 300-task run took about 100 KB of output when the decision needs under 1 KB. The other gaps are relevant log excerpts, cause-aware comparison, incremental waiting, discovery with results, and effective per-job settings. These findings drive the plan rewrite in the next commit. Four CLI issues found along the way were recorded in `development/ISSUES.md` (befa0ab).

## Validation
The fixture script was run from scratch and reproduced the trial's state: 7 failed of 15 jobs in `labA` and 84 failed of 300 in `labC`. No Go code changed, so no Go tests were run. `shellcheck` is not installed here and was not run.

## Remaining
Repeat the trial after each milestone and record a new note. The trial covered only an agent with a shell; an MCP-only client was not tried.
