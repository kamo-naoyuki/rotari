# Issues

Track unresolved bugs, design concerns, and technical debt discovered while working on other tasks.

This file is not a replacement for GitHub issues. Remove an item when it has been resolved, or move it to `Resolved` when keeping a short record is useful.

## Open

- **`show --json` silently ignores `--failed`** (`cmd/rotari/show.go`): `rotari show -r RUN_ID --json --failed` prints output byte-identical to `--json` alone, including successful jobs. This violates the rule that an option must not be accepted and ignored. Expected: select failed jobs, or reject the combination. Found in the [agent trial](2026-10-02-mcp-agent-interface/agent-trial-2026-10-02.md); not yet checked for `--success`, `--unfinished`, or `--filter-*`.

- **A positional run ID cannot be combined with `show --json` or `--report`** (`cmd/rotari/show.go`): `rotari show RUN_ID` works, but `rotari show RUN_ID --json` fails with "a run name selector cannot be combined with run, job, queue, list, log, follow, JSON, or report options". The same run works as `show -r RUN_ID --json`. The message calls the run ID a run name, and `docs/CONCEPTS.md` presents `show RUN_ID` as equivalent to the option form. A positional attempt ID fails the same way: `rotari show ATTEMPT_ID --report`, which `docs/INSPECT.md` gives as an example, fails while `show -j ATTEMPT_ID --report` works.

- **An array job's name is accepted as a dependency but never resolves** (`add`, dependency validation): `add --job-name train --array 1-2 ...` followed by `add --depends-on train ...` (or `--depends-on-finished`, with a plain or matrix dependent) succeeds, and then `check` and `run` fail with `depends on unknown job "train"`. A matrix base name does resolve. Expected: either resolve the array name to all its tasks, or reject it at `add` with a hint to use a stage.

- **`show` project-list hint fails outside the default basedir** (`cmd/rotari/show.go`): with projects in several registered basedirs, `rotari show` lists them and suggests `rotari show -p PROJECT`, which fails with `project "exp" does not exist in state directory <default>` because the hint omits `-b`.

- **`go test ./conformance/...` can report a cached pass after `cmd/rotari` changes** (`conformance/support`, `Run`): the rotari binary is built by a `go build` subprocess, so Go's test cache does not see `cmd/rotari` sources as inputs. On 2026-10-02, after `cmd/rotari/show.go` and `lineage.go` changed, `01-resolution`, `02-lifecycle`, `05-web`, and `06-selectors` printed `(cached)`; `go test -count=1 ./conformance/...` then ran them. `AGENTS.md` and `scripts/check.sh` do not pass `-count=1`. Expected: a conformance run always tests the current binary.

- **`TestWebJobsPageShowsRecentJobs` expects a stale home-link URL** (`internal/webui/webui_test.go`): the rendered Job activity header scopes its home link to the current basedir, while the test expects the literal `href="/"`. The focused history-search tests pass; update this unrelated assertion to match the scoped route.

## Resolved

- **Fingerprint matches were returned in nondeterministic group order** (`internal/model/fingerprint.go`, `MatchFingerprintJobsByMode`): iterating the fingerprint-group map made match output order vary between runs. Groups are now processed by their first occurrence in the current queue; `TestMatchFingerprintJobsRespectsCurrentQueueOrderAcrossGroups` covers stable ordering.

- **Python CLI options could be silently dropped or mis-encoded** (`python/rotari/client.py`): unknown keyword options were ignored, and `run(partial_array=False)` emitted `--partial-array false`, which the CLI parses as a positional argument rather than a false boolean flag. Unknown options now raise `TypeError`, and valueless boolean flags with explicit values use `--flag=value`. Covered by `test_unknown_options_are_rejected_before_invoking_cli` and `test_run_passes_false_for_boolean_value_flag`.

- **Python object ownership and forced JSON options were unnecessarily surprising** (`python/rotari/client.py`): `Job` and `Run` objects were rejected by a separately constructed client even when both clients had identical project context, and methods that always decode JSON exposed a `json` option they silently overrode. Objects now interoperate across clients with matching executable, basedir, project, cwd, and env; JSON output flags are omitted from signatures/docs and explicitly rejected if passed. Covered by `test_objects_can_be_used_with_an_equivalently_configured_client` and `test_json_output_options_are_managed_by_python_api`.

- **The unreproduced intermittent `go test ./cmd/rotari` failure was not actionable**: during sandbox investigation on 2026-09-29, `go test ./cmd/rotari ./internal/state` reported `FAIL github.com/kamo-naoyuki/rotari/cmd/rotari 32.326s`, but the output was incomplete and the failing test was not identified. Subsequent uncached runs all passed: 5 CLI-only runs, 5 runs of both packages, and 15 verbose CLI-only runs. The issue was treated as a suspected flaky test, but no concrete failure was reproduced, so there was no code-level bug to fix. On recurrence, preserve full output and the actual `go test` exit code and identify the failing test before investigating timing or environment dependencies.

- **`wait` could remove recovery locks and report incomplete runs as finished** (`cmd/rotari/wait.go`): selector inspection now preserves stale locks, `wait` rejects newer or invalid summaries once their run is no longer active, and it waits for project finalization before returning a summary. If finalization was interrupted after summary writing, `wait` reports the interrupted state. Covered by `TestCmdWaitProjectSelectorPreservesInterruptedRunLock`, `TestResolveActiveWaitTargetsPreservesStaleRunLock`, `TestCmdWaitDoesNotReturnSummaryBeforeProjectFinalization`, and related summary tests.

- **`TestFollowJobLogReadsAppendedOutputUntilFinished` failed intermittently** (`cmd/rotari/show.go`, `followJobLog`): the loop read the log, then checked the finished marker, so output written between the two reads was dropped and follow returned early. It now re-reads the log once after observing the finished marker.

- **`TestUnlockDerivesInterruptedRun` could kill a supervisor before its job started** (`conformance/01-resolution/export_target_test.go`): the fixture now waits for the job process before simulating interruption, so it reaches a consistent interrupted state.

- **`TestJobControlSelectors` failed once under `scripts/check.sh`** (`conformance/06-selectors/job_control_test.go`): the selector observer now polls all command states until they settle, and the complete selector test passed in a subsequent run.

- **`TestControlFromAnotherHost` raced with local job startup** (`conformance/04-coordination/private_state_test.go`): the fixture rewrote `context.json` after the run was reported as running but before the local wrapper had started, so job-control requests observed a missing job. It now waits for the job process before changing the recorded host; CLI and Web controls then both reject the request without stopping the job.

- **`TestResetOfInterruptedProject` raced with local job startup** (`conformance/04-coordination/private_state_test.go`): the fixture killed coordinator processes as soon as the project was reported running, before the local job wrapper had started and persisted the run state. It now waits for a job process before killing strays, and the reset test reaches the interrupted state reliably.

- **`TestLocalJobTimeoutKillsCommandIgnoringTerm` could fail cleanup on NFS-backed `TMPDIR`** (`internal/executor/timeout_test.go`): the test cleanup now waits for the wrapper's process group to disappear before `t.TempDir` removes the job directory, avoiding delayed `.nfs*` entries.

- **`run` failed where Unix sockets were unavailable** (`internal/server/client.go`, `Start`; `cmd/rotari/server.go`, `runServer`): the run client reached its supervisor over a Unix socket, so sandboxes that block `AF_UNIX` (often with `EPERM`) made `run` unusable, and long base directories needed a fallback socket path. Since a supervisor only ever talks to the `run` that started it, they now talk over pipes it inherits as descriptors 3 and 4; liveness is the `server.lock` flock and `server shutdown` sends `SIGTERM`. Dagu's approach (socket as an optional fast path, files as the control path) was considered but not needed once `cancel`, `suspend`, and `resume` worked through files. Covered by `internal/server/client_test.go`, including `TestJobsDoNotHoldTheClientPipes`.

- **Jobs could run in another command's working directory and environment** (`internal/server/client.go`, `Start`; `cmd/rotari/server.go`, `startSupervisorProcess`): jobs inherit the supervisor's directory and environment, and one supervisor served a whole base directory, so a `run` started while another run was active, or within a minute of `cancel`, ran its jobs where and with what the command that started the supervisor had, while `context.json` and `ROTARI_CWD` named the caller's directory. Each run now starts its own supervisor for its project as a child of `run`, and a supervisor never serves a second run; async runs execute in it instead of a separate worker, and `cancel`, `suspend`, and `resume` no longer start one. Covered by RUN-3 in `conformance/02-lifecycle/lifecycle_test.go`.

- **Local cancellation could miss a command starting after SIGTERM** (`internal/executor/local.go`, `Local.Cancel`; `internal/executor/wrapper.go`, `statusWrapperBody`): dash can defer a TERM trap installed just before the foreground command is spawned until that command finishes, and the new child missed the group signal because it did not exist when the signal was sent. `Cancel` now writes a `cancelled` marker in the job directory before signalling, and the wrapper reads that marker both before launching the command and immediately after, terminating the child and recording `cancelled` with exit 143. Covered by `TestLocalCancelBeforeWrapperStarts` and `TestLocalJobCancelStopsCommandBeforeForegroundExec` in `internal/executor/timeout_test.go`.

- **Some readers ignored run files from a newer rotari** (`internal/state/run_files.go`, `CheckRunVersions`): `show` of a run and of a job, `jobs`, and `copy` of every job treated any error reading `summary.json` or `commands.json` as a missing file, so a newer version was read as absent. They now call `state.CheckRunVersions` first, which fails only for a newer version. Covered by STATE-1 in `conformance/state_test.go`.

- **`unlock` removed the lock of a run that was still running** (`cmd/rotari/unlock.go`, `cmdUnlock`): it did not check the run's coordinator, so on a running project the next `run` started a second runner. It now refuses a local lock whose coordinator is alive, like `reset`, and still removes a lock from another host on the operator's confirmation. Covered by SAFE-4 in `conformance/safety_test.go`.

- **`show --job-id` of a job that never ran failed with "not found in run"** (`cmd/rotari/show.go`, `showJobAttempt`): a job blocked by a failed dependency has no attempt directory, and `show` stopped there while every other view reported it blocked from the summary. It now shows the summary result for a job of the run with no attempt. Covered by DUR-5 in `conformance/fallback_test.go`.

- **`wait` ignored a base directory or project that disagreed with the run registry** (`cmd/rotari/wait.go`, `resolveWaitTarget`): a positional run ID was taken from the registry without the check `--run-id` and every other command apply. It now goes through `resolve.ExistingRun`. Covered by RES-14 in `conformance/resolution_test.go`.

- **Whole-run cancel outside the supervisor left the run interrupted with its jobs running** (`internal/jobcontrol/jobcontrol.go`, `Controller.Cancel`; `internal/server/serve.go`, `Serve`): `Cancel` cancelled jobs itself only in the process holding the run lock and otherwise sent SIGTERM to the lock owner, so an async run (whose `__worker-run` has no handler) and any run cancelled from the Web UI (which signalled the supervisor) stopped their runner instead of their jobs. It now marks the project cancelling and cancels each unfinished job from whichever process handles the request, and the runner finishes the run. `cancel --wait` failed with EOF because the supervisor exited when the run ended, before answering; `Serve` now lets requests in flight finish when the stop leaves no run active. Covered by CAN-1 to CAN-3 in `conformance/cancel_test.go`.

- **Display timestamps were always JST** (`internal/model/time.go`, `FormatDisplayTimestamp`; `internal/joblist/joblist.go`, `FormatTimestamp`): both formatted with a fixed JST zone, so `TZ` was ignored, and the tests asserted JST under `t.Setenv("TZ", ...)`, which cannot change `time.Local` after start. Both now use `time.Local`, the tests set it directly, and `conformance/status_test.go` checks `show` and the Web API under several `TZ` values.

- **`TestServerSyncRunDetachLeavesJobRunning` failed intermittently** (`internal/server/serve.go`, `EndRun`): `EndRun` unlocked before calling `Stop`, so `Busy() == false` and `Stopped() == false` could be seen together. `Stop` is now called under the lock.

- **A planning error after `Begin` left a run without `commands.json`** (`internal/supervisor/run.go`): the supervisor now resolves the reference run and checks selection planning under the state lock before creating a run, for both sync and async starts; a missing source summary no longer leaves an interrupted project.

- **A changed job kept its old result** (`cmd/rotari/change.go`, `applyChangeMutation`; `internal/run/rerun.go`, `jobResult`): in an ordinary queue, `change` of a successful job's command left its origin, so `retry` carried the old command's success and did not run the edit; `retry -j ID` added the job to the failed ones to work around it. A command, environment, or working-directory change now marks the job `Force`, which reruns treat as unfinished, and job selectors no longer combine with result filters (see "Selector combinations" in `contracts/06-selectors.md`).
- **Web job cancel, suspend, and resume did not name their run** (`cmd/rotari/web.go`, `/api/cancel-job`, `/api/suspend-job`, `/api/resume-job`): job IDs are stable across runs, so a page left open on a finished run could act on the same job in the active run. The endpoints now require the page's `run_id`, which jobcontrol checks against the active run.
- **`cancel`/`suspend`/`resume` of a finished run acted on the active run** (`internal/jobcontrol/jobcontrol.go`, `activeLock`; `internal/resolve/resolve.go`, `JobSelection`): a bare run ID or an attempt ID only located the project, so `rotari cancel OLD_RUN_ID` cancelled whatever run was active. The named run is now sent to the supervisor and must be the active one. In the same change, an array job's ID selects its tasks instead of failing as not found, and a job ID without `-p` is looked for in every project's active run, as the selector contract requires.

- **Positional arguments meant different things in similar commands** (`cmd/rotari/unlock.go`, `export.go`, `show.go`, `diff.go`): `unlock`'s and `export`'s positional turned from a project into a run ID when `--project-name` was given, `show` alone did not accept a project name, and `diff` of runs from two projects reported the first as missing. A positional now keeps its meaning whatever the options, `show` tries a project like `wait`, `diff` names the two projects, and the undocumented `run config` alias of `config` is gone.

- **Options after a positional argument were usage errors** (`cmd/rotari/cli_spec.go`, `cliParse`): Go's flag parsing stops at the first positional argument, so `copy RUN_ID --overwrite` failed with a bare usage line. Every command except `add` and `change`, whose positional arguments are the job command, now accepts options anywhere; `--` still ends them.

- **Long base directories made `run` fail with an opaque error** (`internal/server/socket.go`, `SocketPath`): a `<basedir>/server.sock` over the Unix socket path limit failed with `bind: invalid argument`, and the client reported only `Server did not become ready`. Long paths now use `/tmp/rotari-<uid>/<hash>.sock`, and server start failures are written to `server.log`, which the client error names.
- **Executor run-setting flags were read before parsing** (`cmd/rotari/job_executor.go`, `cliExecutorRunSettings`): `run`, `retry`, and the async worker ignored `--<executor>-concurrency`, `-options`, `-submit-interval`, and `-submit-retry-limit` on the command line. The settings are now built by a function called after `fs.Parse`.
- **Flag help text came from the first command that defined the name** (`cmd/rotari/cli_spec.go`, `cliCommandFlag`): `export --help` described `--run-id` as `delete`'s option. Flag registration and the config template now use the parsing command's metadata.
- **`run --async` never started its worker** (`internal/run/worker_args.go`, `WorkerArgs`; `cmd/rotari/main.go`, `parseWorkerRunArgs`): the worker panicked registering `--selection` and `--source-run-id`, which have no CLI metadata, and `--partial-array true` would have left `true` as an extra positional. Every async run was left interrupted. Worker-only flags are now registered directly, the bool is passed as `--partial-array=BOOL`, and `TestWorkerArgsParseBackToOptions` round-trips the arguments.
- **`wait` did not notice a dead run supervisor** (`cmd/rotari/wait.go`, `runEndedWithoutSummary`): it polled forever for a summary that an interrupted run never writes. It now reports the interrupted run and exits 1.
- **Synchronous `run` is cancelled when an agent's command timeout kills the client** (`contracts/03-server-and-command-interfaces.md`, client connection lifecycle): client disconnect still requests cancellation by design. `rotari guide` (`cmd/rotari/assets/agent_guide.md`) and `docs/RUNNING.md` now tell agents to use `run --async` with `wait`.
- **Rule-diagnosis status entries shared the diagnosis list** (`internal/diagnose/analysis.go`, `AnalyzeResult`; `internal/model/model.go`, `JobResult`): no-match and unavailable outcomes were ordinary `RuleDiagnosis` entries, distinguishable only by name, and the policy lived in `cmd/rotari`. They are now `diagnosis_status` / `diagnosis_note`, built in `internal/diagnose`; old summaries are converted on decode.
- **Saved rule diagnoses were never marked stale** (`internal/diagnose/analysis.go`, `RulesVersion`, `Outdated`): results now record a hash of the rule definitions in `diagnosis_rules`, and `show`, reports, and the Web UI note when a saved analysis came from earlier rules. Saved analyses are still not recomputed.
- **`show` of an older attempt mixed in the latest attempt's summary result** (`cmd/rotari/show.go`, `showJobAttempt`; `internal/web/loader.go`, `LoadJobs`): `summary.json` holds only the latest attempt's result, but an older attempt printed its hosts, diagnoses, and timestamps and fell back to its status; the Web UI did the same for an unfinished selected attempt. Both now use `jobstatus.ResolveAttempt`, which applies the summary only to the latest attempt.
- **`completion --help` and `server --help` treated the flag as a subcommand** (`cmd/rotari/completion.go`, `cmd/rotari/server.go`): commands that dispatch on a subcommand never reach a FlagSet, so `--help` failed with `unsupported shell` or `unknown server command`. Both now print shared subcommand help from the CLI metadata.
- **`/dev/null` stdin was treated as a terminal** (`cmd/rotari/terminal.go`, `isTerminal`): only `os.ModeCharDevice` was checked, so `reset` and `copy` with stdin from `/dev/null` prompted and failed with `EOF` instead of printing the non-interactive guidance. It now queries termios settings.
- **Copying part of a stage rejected its dependents** (`cmd/rotari/copy.go`, `copyRunToQueue`): the excluded-dependency check required every stage member to have succeeded, including the members being copied, so `retry` failed after any stage member failed. Only omitted members are checked now, and the stage dependency is kept while any member is copied.
- **The `example-shellcheck` pre-commit hook never ran** (`.pre-commit-config.yaml`): its `files: ^example\.sh$` pattern did not match `scripts/example*.sh`, and `bash -n a b` checks only the first file. The hook now matches every example script and checks each one separately.
- **Matrix base-name dependencies broke partial queue edits** (`internal/model/dependencies.go`, `ClearMatrixGroup`; `cmd/rotari/copy.go`): a dependency on a matrix base name stopped resolving once `change` or `remove` cleared the group's provenance, and `copy` (including `retry`) did not recognize base names at all. Clearing provenance now rewrites such dependencies to the remaining member names, and `copy` checks base names like stages.
- **Running an imported queue with new jobs failed from the CLI** (`cmd/rotari/run_selection.go`, `planImportedWorkflow`): the run server records the new run as `LastRunID` before planning, and jobs without an origin fell back to that run's missing summary. Origin-less imported jobs are now planned as new work without a previous-run lookup.
- **`show` job hid manual acceptance** (`cmd/rotari/show.go`, `showJobAttempt`): an accepted job printed only the ordinary carry note and the source attempt's failing exit code, while `show` run and the Web table showed `success (accepted)`. It now prints the accepted status and follows `Origin.AttemptID`.
- **Workflow import ignored local results of non-latest attempts** (`cmd/rotari/workflow_reconcile.go`, `resolveAttempt`): only wrapper `status.json` was read, so a local-executor attempt that was not the summary's latest failed with "has no completed result". It now reads the local `status` result first, matching run planning.
- **Workflow import rejected unchanged matrix runs** (`cmd/rotari/workflow_reconcile.go`, `reconcileCommandLeaves`): every matrix member was resolved against the group's job-level `attempt_id`, so any group with two or more successful combinations failed with "attempt belongs to job". Matrix members now use their own instance attempt or recover from the listed source run.
- **Workflow import of a filtered array retry silently accepted stale failed tasks** (`cmd/rotari/workflow_reconcile.go`, `listedCommandRun`): leaves without a manifest attempt were read from the run named by the job-level anchor attempt. They are now recovered from the listed source run that supplied the command, following carried attempt IDs to their original run.
- **SSH metadata read errors are reported as "job is not running"** (`internal/executor/ssh.go`, `readSSHMetadata`): fixed to treat only missing metadata as "job is not running" while preserving distinct errors for malformed or unreadable state.
- **`state.WriteJSON` ignores the configured shared/private file modes** (`internal/state/store.go`, `cmd/rotari/state_store.go`): fixed to use the configured `DirectoryMode()` / `FileMode()` instead of hard-coded private defaults.
- **Production logging depends directly on the Go test runtime** (`cmd/rotari/color.go`, `jobLogf`): fixed by removing the `testing.Testing()` dependency and exposing an explicit package-level log hook that tests can override without affecting production behavior.
- **`show RUN` missed queue edits to environment, stage, timeout, and retry settings** (`cmd/rotari/show.go`, `compareQueueWithRun`; `internal/rundiff/rundiff.go`, `SpecChanges`): fixed by reusing the `diff` definition-field comparison for queue-vs-run reporting.
- **Supervisor async starts could report an error after launching the run** (`internal/supervisor/run.go`, `StartRun`; `internal/server/serve.go`, `Handle`): path validation now completes before the async goroutine starts, preventing a start error from causing duplicate run cleanup.
- **Supervisor failure messages left a missing attempt ID blank** (`internal/supervisor/run.go`, `runObserver`; `internal/supervisor/messages.go`, `failedJobHints`): the existing job-ID fallback is now used in the displayed attempt ID as well as the inspection command. Covered by `TestFailedJobHintsUsesJobIDWhenAttemptIDIsMissing`.
- **Lineage Web summaries counted blocked jobs as failed** (`internal/web/loader.go`, `buildLineageSummary`): dependency-blocked results now use the same blocked classification as CLI lineage. Covered by `TestBuildLineageSummaryCountsBlockedJobsSeparately`.
- **Lineage marked newly blocked jobs as carried** (`internal/runview/run.go`, `LoadRun`): carried detection now excludes results newly blocked by a failed dependency. Covered by `TestLoadRunDoesNotCarryAnewlyBlockedJob`.
- **Lineage grids split jobs renamed through an origin** (`internal/runlineage/runlineage.go`, `CompareGrid`): grid rows now follow `(run ID, job ID)` origins across runs. Covered by `TestCompareGridFollowsOriginAcrossRenamedJobs`.
- **Lineage ignored output and stream settings in definition changes** (`internal/runlineage/runlineage.go`, `SpecChanges`): output, error, log mode, and open mode changes are now reported. Covered by `TestSpecChangesIncludesOutputAndOpenSettings`.
