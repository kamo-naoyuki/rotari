- **Workflow manifest docs implied implicit carry for an unfiltered run** ([docs/WORKFLOW_MANIFESTS.md](../docs/WORKFLOW_MANIFESTS.md), [docs/FAQ.md](../docs/FAQ.md), [contracts/02-run-lifecycle-and-execution.md](../contracts/02-run-lifecycle-and-execution.md)): the guides now recommend `retry` to execute failed/unfinished manifest jobs and carry completed results, and state that unfiltered `run` executes the entire queue. - **A changed job kept its old result** (`cmd/rotari/change.go`, `applyChangeMutation`; `internal/run/rerun.go`, `jobResult`): in an ordinary queue, `change` of a successful job's command left its origin, so `retry` carried the old command's success and did not run the edit; `retry -j ID` added the job to the failed ones to work around it. A command, environment, or working-directory change now marks the job `Force`, which reruns treat as unfinished, and job selectors no longer combine with result filters (see "Selector combinations" in `contracts/06-selectors.md`).
- **Web job cancel, suspend, and resume did not name their run** (`cmd/rotari/web.go`, `/api/cancel-job`, `/api/suspend-job`, `/api/resume-job`): job IDs are stable across runs, so a page left open on a finished run could act on the same job in the active run. The endpoints now require the page's `run_id`, which jobcontrol checks against the active run.
- **`cancel`/`suspend`/`resume` of a finished run acted on the active run** (`internal/jobcontrol/jobcontrol.go`, `activeLock`; `internal/resolve/resolve.go`, `JobSelection`): a bare run ID or an attempt ID only located the project, so `rotari cancel OLD_RUN_ID` cancelled whatever run was active. The named run is now sent to the supervisor and must be the active one. In the same change, an array job's ID selects its tasks instead of failing as not found, and a job ID without `-p` is looked for in every project's active run, as the selector contract requires.

- **Positional arguments meant different things in similar commands** (`cmd/rotari/unlock.go`, `export.go`, `show.go`, `diff.go`): `unlock`'s and `export`'s positional turned from a project into a run ID when `--project-name` was given, `show` alone did not accept a project name, and `diff` of runs from two projects reported the first as missing. A positional now keeps its meaning whatever the options, `show` tries a project like `wait`, `diff` names the two projects, and the undocumented `run config` alias of `config` is gone.

- **Options after a positional argument were usage errors** (`cmd/rotari/cli_spec.go`, `cliParse`): Go's flag parsing stops at the first positional argument, so `copy RUN_ID --overwrite` failed with a bare usage line. Every command except `add` and `change`, whose positional arguments are the job command, now accepts options anywhere; `--` still ends them.

- **Long base directories made `run` fail with an opaque error** (`internal/server/socket.go`, `SocketPath`): a `<basedir>/server.sock` over the Unix socket path limit failed with `bind: invalid argument`, and the client reported only `Server did not become ready`. Long paths now use `/tmp/rotari-<uid>/<hash>.sock`, and server start failures are written to `server.log`, which the client error names.
- **Executor run-setting flags were read before parsing** (`cmd/rotari/job_executor.go`, `cliExecutorRunSettings`): `run`, `retry`, and the async worker ignored `--<executor>-concurrency`, `-options`, `-submit-interval`, and `-submit-retry-limit` on the command line. The settings are now built by a function called after `fs.Parse`.
- **Flag help text came from the first command that defined the name** (`cmd/rotari/cli_spec.go`, `cliCommandFlag`): `export --help` described `--run-id` as `delete`'s option. Flag registration and the config template now use the parsing command's metadata.
- **`run --async` never started its worker** (`internal/run/worker_args.go`, `WorkerArgs`; `cmd/rotari/main.go`, `parseWorkerRunArgs`): the worker panicked registering `--selection` and `--source-run-id`, which have no CLI metadata, and `--partial-array true` would have left `true` as an extra positional. Every async run was left interrupted. Worker-only flags are now registered directly, the bool is passed as `--partial-array=BOOL`, and `TestWorkerArgsParseBackToOptions` round-trips the arguments.
- **`wait` did not notice a dead run supervisor** (`cmd/rotari/wait.go`, `runEndedWithoutSummary`): it polled forever for a summary that an interrupted run never writes. It now reports the interrupted run and exits 1.
- **Synchronous `run` is cancelled when an agent's command timeout kills the client** (`contracts/03-server-and-command-interfaces.md`, client connection lifecycle): client disconnect now detaches by default; `--disconnect-action cancel` or `ROTARI_DISCONNECT_ACTION=cancel` restores cancellation.
- **Rule-diagnosis status entries shared the diagnosis list** (`internal/diagnose/analysis.go`, `AnalyzeResult`; `internal/model/model.go`, `JobResult`): no-match and unavailable outcomes were ordinary `RuleDiagnosis` entries, distinguishable only by name, and the policy lived in `cmd/rotari`. They are now `diagnosis_status` / `diagnosis_note`, built in `internal/diagnose`; old summaries are converted on decode.
- **Saved rule diagnoses were never marked stale** (`internal/diagnose/analysis.go`, `RulesVersion`, `Outdated`): results now record a hash of the rule definitions in `diagnosis_rules`, and `show`, reports, and the Web UI note when a saved analysis came from earlier rules. Saved analyses are still not recomputed.
- **`show` of an older attempt mixed in the latest attempt's summary result** (`cmd/rotari/show.go`, `showJobAttempt`; `internal/web/loader.go`, `LoadJobs`): `summary.json` holds only the latest attempt's result, but an older attempt printed its hosts, diagnoses, and timestamps and fell back to its status; the Web UI did the same for an unfinished selected attempt. Both now use `jobstatus.ResolveAttempt`, which applies the summary only to the latest attempt.
- **`completion --help` and `server --help` treated the flag as a subcommand** (`cmd/rotari/completion.go`, `cmd/rotari/server.go`): commands that dispatch on a subcommand never reach a FlagSet, so `--help` failed with `unsupported shell` or `unknown server command`. Both now print shared subcommand help from the CLI metadata.
- **`/dev/null` stdin was treated as a terminal** (`cmd/rotari/terminal.go`, `isTerminal`): only `os.ModeCharDevice` was checked, so `reset` and `copy` with stdin from `/dev/null` prompted and failed with `EOF` instead of printing the non-interactive guidance. It now queries termios settings.
- **Copying part of a stage rejected its dependents** (`cmd/rotari/copy.go`, `copyRunToQueue`): the excluded-dependency check required every stage member to have succeeded, including the members being copied, so `retry` failed after any stage member failed. Only omitted members are checked now, and the stage dependency is kept while any member is copied.
- **The `example-shellcheck` pre-commit hook never ran** (`.pre-commit-config.yaml`): its `files: ^example\.sh$` pattern did not match `scripts/example*.sh`, and `bash -n a b` checks only the first file. The hook now matches every example script and checks each one separately.
- **Matrix base-name dependencies broke partial queue edits** (`internal/model/dependencies.go`, `ClearMatrixGroup`; `cmd/rotari/copy.go`): a dependency on a matrix base name stopped resolving once `change` or `remove` cleared the group's provenance, and `copy` (including `retry`) did not recognize base names at all. Clearing provenance now rewrites such dependencies to the remaining member names, and `copy` checks base names like stages.
- **Running an imported queue with new jobs failed from the CLI** (`cmd/rotari/run_selection.go`, `planImportedWorkflow`): the run server records the new run as `LastRunID` before planning, and jobs without an origin fell back to that run's missing summary. Origin-less imported jobs are now planned as new work without a previous-run lookup.
- **`show` job hid manual acceptance** (`cmd/rotari/show.go`, `showJobAttempt`): an accepted job printed only the ordinary carry note and the source attempt's failing exit code, while `show` run and the Web table showed `success (accepted)`. It now prints the accepted status and follows `Origin.AttemptID`.
- **Workflow import ignored local results of non-latest attempts** (`cmd/rotari/workflow_reconcile.go`, `resolveAttempt`): only wrapper `status.json` was read, so a local-executor attempt that was not the summary's latest failed with "has no completed result". It now reads the local `status` result first, matching run planning.
- **Workflow import rejected unchanged matrix runs** (`cmd/rotari/workflow_reconcile.go`, `reconcileCommandLeaves`): every matrix member was resolved against the group's job-level `attempt_id`, so any group with two or more successful combinations failed with "attempt belongs to job". Matrix members now use their own instance attempt or recover from the listed source run.
- **Workflow import of a filtered array retry silently accepted stale failed tasks** (`cmd/rotari/workflow_reconcile.go`, `listedCommandRun`): leaves without a manifest attempt were read from the run named by the job-level anchor attempt. They are now recovered from the listed source run that supplied the command, following carried attempt IDs to their original run.
- **SSH metadata read errors are reported as "job is not running"** (`internal/executor/ssh.go`, `readSSHMetadata`): fixed to treat only missing metadata as "job is not running" while preserving distinct errors for malformed or unreadable state.
- **`state.WriteJSON` ignores the configured shared/private file modes** (`internal/state/store.go`, `cmd/rotari/state_store.go`): fixed to use the configured `DirectoryMode()` / `FileMode()` instead of hard-coded private defaults.
- **Production logging depends directly on the Go test runtime** (`cmd/rotari/color.go`, `jobLogf`): fixed by removing the `testing.Testing()` dependency and exposing an explicit package-level log hook that tests can override without affecting production behavior.
- **`show RUN` missed queue edits to environment, stage, timeout, and retry settings** (`cmd/rotari/show.go`, `compareQueueWithRun`; `internal/rundiff/rundiff.go`, `SpecChanges`): fixed by reusing the `diff` definition-field comparison for queue-vs-run reporting.
- **Supervisor async starts could report an error after launching the run** (`internal/supervisor/run.go`, `StartRun`; `internal/server/serve.go`, `Handle`): path validation now completes before the async goroutine starts, preventing a start error from causing duplicate run cleanup.
- **Supervisor failure messages left a missing attempt ID blank** (`internal/supervisor/run.go`, `runObserver`; `internal/supervisor/messages.go`, `failedJobHints`): the existing job-ID fallback is now used in the displayed attempt ID as well as the inspection command. Covered by `TestFailedJobHintsUsesJobIDWhenAttemptIDIsMissing`.
- **Lineage Web summaries counted blocked jobs as failed** (`internal/web/loader.go`, `buildLineageSummary`): dependency-blocked results now use the same blocked classification as CLI lineage. Covered by `TestBuildLineageSummaryCountsBlockedJobsSeparately`.
- **Lineage marked newly blocked jobs as carried** (`internal/runview/run.go`, `LoadRun`): carried detection now excludes results newly blocked by a failed dependency. Covered by `TestLoadRunDoesNotCarryAnewlyBlockedJob`.
- **Lineage grids split jobs renamed through an origin** (`internal/runlineage/runlineage.go`, `CompareGrid`): grid rows now follow `(run ID, job ID)` origins across runs. Covered by `TestCompareGridFollowsOriginAcrossRenamedJobs`.
- **Lineage ignored output and stream settings in definition changes** (`internal/runlineage/runlineage.go`, `SpecChanges`): output, error, log mode, and open mode changes are now reported. Covered by `TestSpecChangesIncludesOutputAndOpenSettings`.

- **Recent jobs omitted carried-result annotations and origin timestamps** ([internal/joblist/joblist.go](../internal/joblist/joblist.go), `collectRun`): the shared carried predicate now marks the row `(carried)`, and shared timestamp resolution follows its origin attempt. `TestCollectRunUsesCarriedStatusAndOriginTimestamps` reproduces the missing row and checks the origin times; `TestCarriedJobsReadAsCarriedDuringTheRun` also checks CLI output against the original attempt. DUR-7 now records this recent-jobs behavior.
